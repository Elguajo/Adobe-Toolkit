# Tool Routing

Choose by the question **and** preferred implementation registry.

```text
Intent / location unknown in unfamiliar repo → Semble when configured
Known symbol / references / implementations / semantic refactor → Serena
Tiny exact file/string edit → native exact tools
Verbose supported shell/test/build/git output → RTK when safe
Implementation/TDD/debug discipline → Superpowers when configured
Challenge/review/browser QA/release evidence → gstack selectively
Fresh version-sensitive library/API docs → Context7; primary official docs when critical
Deep formal specification justified → GitHub Spec Kit Advanced Spec Mode
```

If a materially useful preferred tool is absent, route to `tooling-bootstrap` rather than silently deleting the preference. Do not interrupt tiny work just to install optional tooling. One discovery question gets one primary route; a second tool must answer a distinct question, resolve ambiguity, or be fallback after failure.

External tools never own Brief, Architecture, Roadmap, current phase, ADR rationale, or project handoff.
